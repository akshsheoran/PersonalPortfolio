Teaching LLM agents to forget the right things

Memory systems for LLM agents, such as MemGPT and Mem0, keep writing to long-term memory and rarely delete anything. Over months, the store fills with duplicates, outdated facts and entries that contradict each other. Retrieval then pulls that junk back into the prompt, and answers get worse.

Our team is studying how memory quality affects retrieval, and whether cleaning memory before retrieval helps vector-based and graph-based retrieval equally. I lead the cognitive memory module: working memory, episodic memory, reflection, forgetting, and how the four fit into one lifecycle.

  • Literature survey and research gap presentedReview 1 · four modules, from RAG to memory benchmarks
  • Classifying junk memory and testing its removalIn progress
  • Conference paper in preparationPatent filing being explored

The method itself stays off this page until filing. Happy to talk about the problem space in person.

Five kinds of junk memory

  • redundantThe same fact stored more than once."Lives in Vellore" + "Based in Vellore"
  • outdatedTrue once, replaced by something newer."Is in first year"
  • contradictoryTwo entries that cannot both be true."Prefers Java" vs "Never uses Java"
  • irrelevantNever useful for any future question.Small talk, filler turns
  • temporaryUseful for one session, then expired."Remind me in 5 minutes"

Memory lifecycle · my module

Measured on LoCoMo · LongMemEval · MemBench

  1. Working memoryWhat the agent holds in its context window right now.
  2. Episodic memoryA timestamped log of past interactions.
  3. ReflectionMany episodes condensed into reusable knowledge.
  4. ForgettingRetention, deduplication and expiry. My focus.
  5. Updated memoryA smaller, cleaner store that retrieves better.

Road hazard mapping from everyday vehicles

A low-cost sensor node rides on a vehicle and feels the road through a motion sensor. It decides on the device itself whether a jolt was a pothole, tags it with GPS, and sends only that event to a backend. A hazard reaches the public map only after several independent vehicles report it in the same place.

edge node · acceleration magnitudeillustrative signal
road vibration · stays on device hazard event · sent detection threshold
  1. SenseIMU and GPS sampled continuously.
  2. ProcessFiltering and features on the ESP32.
  3. DetectThreshold or decision-tree classifier.
  4. GeotagCoordinates and timestamp attached.
  5. SendOnly the event, never raw data.
  6. ConfirmConsensus across vehicles.
  7. MapConfirmed hazards shown publicly.
